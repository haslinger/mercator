It depends on where you tested.

**Locally (dev server, `localhost`): it never arrives.** Mollie rejects webhook URLs it can't reach, so in development the adapter creates the payment without a `webhookUrl` (`public_url/1` in [mollie.ex:125-131](lib/mercator/payments/mollie.ex#L125-L131)). The order's status is only updated when the customer comes back to the return page.

**On the home server (https://biber.mittenin.at):**
- **Paid, failed or canceled:** Mollie calls `POST /payments/mollie/webhook` with the payment id within a few seconds of the status changing. With a `test_…` key, that's the moment you pick the outcome on Mollie's test page. This usually happens before or at about the same time as the redirect back to the shop.
- **When the payment is created:** no call. The status is `open`, and Mollie doesn't report that.
- **If you abandon the checkout:** the call only comes when the payment expires. For most payment methods that's about 15 minutes; the payment's `expiresAt` gives the exact time.
- **If your endpoint didn't answer 200:** Mollie retries several times, spread over about a day.

A missing call on the server most likely means one of two things:
- The deployed build doesn't have the Mollie commit (b957486) yet.
- The reverse proxy blocks or rate-limits the POST.

To check, look for the request in `docker compose logs app` (search for `/payments/mollie/webhook`), and look at the payment in Mollie's dashboard, which shows whether a webhook URL was set. If the payment there has no webhook URL, it was created from a non-HTTPS or localhost base URL.

### Claude · 17:21

This shows the app's log from 18:25 to 18:50 on 2026-10-15, filtered to webhook lines:

```sh
docker compose logs -t --since 2026-10-15T18:25:00+02:00 --until 2026-10-15T18:50:00+02:00 app | grep -i -B2 -A5 webhook
```

- `-t` puts Docker's timestamp in front of each line, so you can see exactly when the request came in.
- The `+02:00` offset matters. Without it, Docker may read the times as UTC, which would shift the window by two hours.
- `-B2 -A5` also prints the lines just before and after each match. That way you see the status line (`Sent 200 in …`) and any payment log output with it.

If nothing shows up, drop the `grep` and look through the whole window. You might find a request that was logged differently, or an error.

If there's still nothing, the request probably never reached the app. Then the next places to look are the reverse proxy's access log for that time and the webhook call log on the payment's page in Mollie's dashboard.
