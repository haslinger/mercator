### Claude · 10:22

I've added a Caddy example to the reverse proxy section of [DOCKER.md](DOCKER.md), right after the nginx one, and committed it as `d06dba0`. It isn't pushed yet.

```caddy
biber.mittenin.at {
    request_body {
        max_size 50MB   # uploads (product images, media, chat files)
    }
    reverse_proxy 127.0.0.1:4010
}
```

It's shorter than the nginx version because Caddy does most of it by default:

- It gets the HTTPS certificate by itself.
- It forwards WebSockets, which LiveView needs, and passes on the original host and client address.
- It speaks HTTP/1.1 to the app, which keeps the app's web server away from its open HTTP/2 issue.

The upload limit is the only extra setting. The section also says how to reload Caddy after changing it.

The note below the examples now lists a Caddy container too. A proxy running in a container can't reach `127.0.0.1:4010` on the host.

If Caddy runs directly on the host, the app sees its requests coming from Docker's network. That network is in the default `TRUSTED_PROXIES`, so you don't need to change anything for client IPs or rate limits.
